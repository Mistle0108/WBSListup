# WBS List up — 상세 개발 기획서

작성일: 2026-11-08 · 수정일: 2026-11-09 · 개정: 04 · 상태: 구현 기준 초안

제품명: **WBS List up**. 상표·도메인 사용 가능 여부는 확인하지 않았다.

## 1. 목적과 확정 요구

여러 해에 걸친 프로젝트를 계층형 작업 목록과 가로 일정 막대로 관리한다. 전체 계획에서 개별 작업까지 확대하고, 각 작업에 자유 배치 메모와 정형 문서를 함께 보관한다.

이번 개정의 확정 요구는 다음과 같다.

1. 일정 보드에서 Ctrl+휠을 올리면 확대, 내리면 축소한다. 일반 휠은 가로 스크롤로 사용한다.
2. 상단의 표시 시작일·종료일 입력, 기간 단위 선택, 줌 슬라이더, 확대·축소 버튼을 제거한다.
3. 시간 눈금은 확대 배율에 따라 자동으로 전환한다.
4. 프로젝트 목록을 화면 왼쪽으로 이동한다.
5. 프로젝트 사이드바를 접고 펼칠 수 있게 한다. 상단 토글은 접힌 상태에서도 남는다.
6. 작업 계층·그룹, 호버 요약, 더블클릭 상세, 자유 배치 노트와 문서는 유지한다.
7. 프로젝트 상세에서 문서를 개수 제한 없이 추가하고, 창 높이를 넘으면 내부를 세로 스크롤한다.
8. 작업 막대를 좌우로 드래그하여 시작일·종료일을 함께 이동한다. 일정 잠금으로 날짜 변경을 막을 수 있다.

‘기간 변경 UI 제거’는 **화면에 보이는 기간을 직접 지정하는 컨트롤 제거**로 해석한다. 작업 상세의 시작일·종료일은 실제 일정을 기록하는 입력이므로 유지한다. 휠은 보기만 변경하며 작업 날짜를 수정하지 않는다.

이 문서의 세부 수치와 저장·편집 규칙은 구현을 위한 제안이다. 플랫폼과 공동 편집 여부는 미확정이다. 1차 범위는 단일 사용자·단일 저장소를 기준으로 잡는다. 이 가정이 달라지면 저장 계층의 설계를 조정한다.

## 2. 정보 구조와 용어

| 용어 | 의미 |
| --- | --- |
| 프로젝트 폴더 | 왼쪽 사이드바에서 프로젝트를 분류하는 컨테이너 |
| 프로젝트 | 독립적인 작업 트리와 타임라인을 가진 관리 단위 |
| 작업 그룹 | 프로젝트 내부에서 작업과 하위 그룹을 묶는 노드 |
| 작업 | 이름, 기간, 개요, 호버 요약, 보드, 문서를 가진 실행 단위 |
| 일정 보드 | WBS 작업명과 시간축 막대를 함께 표시하는 메인 화면 |
| 표시 구간 | 현재 화면의 왼쪽 날짜부터 오른쪽 날짜까지의 범위 |
| 노트 보드 | 개별 작업 상세 안의 자유 배치 메모 공간 |

프로젝트 폴더와 작업 그룹은 별개 구조다. 사이드바는 프로젝트를 선택하는 곳이고, 작업 그룹 편집은 메인 WBS에서 수행한다.

```text
워크스페이스
├─ 제품 개발 [프로젝트 폴더]
│  ├─ 신규 제품 [하위 폴더]
│  │  └─ 프로젝트 A
│  └─ 프로젝트 B
└─ 프로젝트 C

프로젝트 A
├─ 기획 [작업 그룹]
│  ├─ 요구사항 정리 [작업]
│  └─ 화면 설계 [작업 그룹]
│     ├─ 일정 보드 [작업]
│     └─ 작업 상세 [작업]
└─ 검증 [작업]
```

폴더와 작업 그룹은 중첩을 허용한다. 프로젝트를 다른 프로젝트 아래에 넣지는 않는다. 최상위 작업도 허용한다. WBS 번호는 현재 정렬과 계층에서 산출하며 데이터 식별자로 사용하지 않는다.

```text

│ [사이드바 토글] 워크스페이스                              저장 상태   │

│ 프로젝트         │ 폴더 경로 / 프로젝트명                           │

│                  ├────────────────┬─────────────────────────────────┤

│                  │ ▾ 2. 구현      │            ━━━━━━━━━━━━━        │

└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 상단과 헤더

- 상단 왼쪽 사이드바 토글은 항상 접근 가능하다. 아이콘·접근성 이름으로 펼침과 접힘을 전달한다.
- 프로젝트명과 폴더 경로를 표시한다.
- 표시 구간과 눈금은 읽기 전용이다. 클릭해 기간을 지정하는 기능을 두지 않는다.
- 프로젝트 전체 기간은 날짜가 있는 작업들의 최소 시작일과 최대 종료일로 요약한다. 별도의 상단 기간 설정은 두지 않는다.
- 일정 헤더의 추가 버튼은 작업과 그룹에 한정한다. 프로젝트명 옆에 상세 버튼을 두고 프로젝트 메뉴에는 상세 열기·이름 변경·이동·삭제를 둔다. 문서 추가는 프로젝트 상세에서 제공한다.
- 저장 상태는 저장 중 / 저장됨 / 저장 실패를 구분한다.

### 3.2 프로젝트 사이드바

- 기본 너비 240px, 초기 상태는 펼침을 제안한다.
- 접으면 사이드바가 차지하던 너비를 메인 화면이 사용한다. 별도 빈 레일은 남기지 않는다.
- 접기/펼치기 시 선택 프로젝트, 선택 작업, 그룹 펼침 상태, 화면 중심 날짜, 날짜당 픽셀 수를 유지한다. 늘어난 공간만큼 더 많은 날짜가 보인다.
- 사이드바 자체는 독립적으로 세로 스크롤한다.
- 폴더 펼침 버튼과 이름 선택 영역을 구분한다. 폴더 클릭이 프로젝트 선택을 바꾸지는 않는다.
- 선택 프로젝트는 배경과 표시자로 구분한다.
- 생성 위치는 선택 폴더가 있으면 그 폴더, 없으면 최상위다.
- 폴더·프로젝트 이동 메뉴를 제공한다. 드래그 정렬은 후속 단계로 분리한다.
- 이름 변경은 인라인 입력 또는 작은 편집창으로 제공한다. 빈 이름을 저장할 수 없다.
- 비어 있지 않은 폴더·프로젝트 삭제 시 포함 개수를 보여주고 확인한다. 취소 시 데이터를 바꾸지 않는다.
- 재실행 시 사이드바 상태, 선택 프로젝트, 펼친 폴더를 복원한다.
- 1차 화면은 데스크톱 너비 1024px 이상을 기준으로 설계한다. 모바일 전용 화면은 범위에서 제외한다.

### 3.3 WBS와 타임라인

- 작업명 영역 기본 너비 280px, 행 높이 48px를 제안한다.
- 두 영역은 하나의 가시 행 목록과 세로 스크롤 위치를 공유한다. 작업명과 막대 행이 어긋나면 안 된다.
- 시간축 헤더는 세로 스크롤 중 상단에 고정한다.
- 긴 이름은 줄임표로 표시하고 포커스 또는 호버 시 전체 이름을 제공한다.
- 그룹은 접기 아이콘과 요약 막대로, 작업은 시작~종료일까지 채워진 막대로 표현한다.
- 그룹을 접으면 하위 행만 숨긴다. 기간 집계에는 숨긴 작업도 포함한다.
- 여러 해에 걸친 작업도 실제 날짜를 보존한다. 화면 밖 부분만 렌더링에서 클리핑한다.
- 화면 밖으로 이어지는 막대 끝은 계속됨 표시로 실제 종료점과 구분한다.
- 일반 작업 막대를 좌우로 드래그하면 기간 길이를 유지하며 시작일·종료일을 함께 이동한다. 잠긴 작업은 이동할 수 없다. 그룹 요약 막대는 직접 드래그하지 않는다. 시작·종료일 개별 변경은 상세 화면에서 한다.

## 4. 시간 탐색 입력 명세

### 4.1 영역별 입력

| 위치 / 입력 | 결과 |
| --- | --- |
| 일정 막대 영역에서 Ctrl+휠 위 | 확대: 보이는 날짜 수 감소 |
| 일정 막대 영역에서 Ctrl+휠 아래 | 축소: 보이는 날짜 수 증가 |
| 일정 막대 영역에서 일반 휠 위 / 아래 | 가로 스크롤: 과거 / 미래로 이동 |
| 시간축 헤더에서 휠 | Ctrl 유무에 따라 같은 확대·축소 또는 가로 스크롤 |
| 작업명 목록에서 휠 | 작업 행 세로 스크롤 |
| 사이드바에서 휠 | 프로젝트 목록 세로 스크롤 |
| 트랙패드 수평 스크롤 | 과거·미래로 수평 이동 |
| 일정 빈 공간을 왼쪽 버튼으로 드래그 | 잡아 끄는 방향대로 시간축 이동 |
| 잠기지 않은 작업 막대를 좌우로 드래그 | 기간 길이를 유지하며 실제 일정 이동 |
| 작업 행의 잠금 버튼 | 일정 잠금·해제 |
| 일정 보드에 포커스 후 + / − | 화면 중앙 기준 확대·축소 |
| 일정 보드에 포커스 후 ← / → | 화면 폭의 15%만큼 시간 이동 |
| 일정 보드에 포커스 후 ↑ / ↓ | 한 행만큼 세로 이동 |
| 작업명·막대 더블클릭 또는 막대 포커스 후 Enter | 작업 상세 열기 |

휠은 해당 영역에서만 처리한다. 문서나 상세 입력창 위의 휠이 배경 타임라인을 바꾸어서는 안 된다. 일정 막대 영역과 시간축 헤더에서 Ctrl+휠을 처리할 때는 브라우저 기본 확대를 차단하고 타임라인만 확대·축소한다. 그 밖의 영역에서는 기본 입력 동작을 유지한다. Meta를 Ctrl의 대체 키로 지정하지 않는다.

Ctrl 없이 입력한 휠은 가로 스크롤로 처리한다. 트랙패드 대각 입력은 절댓값이 큰 축 하나만 사용하고, 세로 입력은 가로 이동량으로 변환한다. 음수는 과거, 양수는 미래로 이동한다. Ctrl을 누르면 세로 휠 값으로 확대·축소하며 가로 스크롤을 동시에 수행하지 않는다. Ctrl과 함께 들어온 순수 가로 입력은 무시한다. 작업 행 세로 탐색은 작업명 영역 또는 세로 스크롤바를 사용한다.

### 4.2 포인터 기준 확대

Ctrl+휠을 움직이기 직전 마우스 아래에 있던 날짜가 확대 후에도 같은 화면 위치에 남아야 한다. 관심 작업을 확대하는 동안 화면 밖으로 밀려나는 현상을 방지한다.

```text
W = 타임라인 표시 너비(px)
L = 현재 왼쪽 날짜의 일 단위 좌표
S = 현재 표시 일수
x = 타임라인 왼쪽부터 포인터까지 거리(px)
r = clamp(x / W, 0, 1)
A = L + r × S
S' = clamp(S × exp(delta × k), 최소 표시 일수, 최대 표시 일수)
L' = A - r × S'
```

- delta는 Ctrl을 누른 상태에서 입력한 정규화된 세로 휠 값이다. 음수는 확대, 양수는 축소다. 일반 휠에는 이 확대 공식을 적용하지 않는다.
- deltaMode의 픽셀·줄·페이지 단위를 정규화한다.
- 초기 감도는 정규화 픽셀당 k=0.002를 제안한다. 이벤트별 delta는 ±120 이내로 제한하고 실제 마우스·트랙패드에서 조정한다.
- 이벤트는 프레임 단위로 모아서 반영한다. 휠마다 전체 데이터 저장을 수행하지 않는다.
- 최소 표시 구간 7일, 최대 30년을 초기 기준으로 한다. 이는 배율 제한이며 프로젝트가 저장할 수 있는 전체 기간의 제한은 아니다.
- 한계 배율에서 추가 Ctrl+휠 입력으로 기준 날짜나 위치가 바뀌어서는 안 된다. 일반 휠의 가로 스크롤은 계속 가능하다.
- 줌·팬·행 스크롤 시작 시 툴팁을 닫는다.

### 4.3 자동 눈금

날짜당 픽셀 수로 눈금을 선택하되, 실제 월·분기·연도 경계에 선을 그린다. 월을 30일, 연도를 365일로 고정하여 위치를 계산하면 안 된다.

| 주 눈금 | 선택 기준 예시 | 보조 헤더 |
| --- | --- | --- |
| 일 | 하루 너비 ≥ 48px | 연·월 |
| 주 | 한 주 너비 ≥ 65px | 연·월, 주 시작 날짜 |
| 월 | 평균 한 달 너비 ≥ 65px | 연 |
| 분기 | 한 분기 너비 ≥ 65px | 연 |
| 년 | 위 기준보다 작을 때 | 필요 시 2·5·10년 간격 라벨 |

폭 비교용 평균 일수와 실제 경계 계산을 분리한다. 주 시작은 월요일이다. 월말·윤년을 달력 규칙대로 처리한다. 30년 보기나 좁은 화면에서는 라벨 간격을 건너뛰어 중첩을 방지한다. 눈금 전환 경계에는 약 10%의 여유 구간을 두어 미세 입력마다 눈금이 반복 전환되지 않게 한다.

### 4.4 최초 진입·복원·화면 크기 변경

- 처음 여는 프로젝트는 날짜 지정 작업 전체와 양쪽 5% 여백을 포함한다.
- 작업이 하루뿐이면 최소 7일, 작업이 없으면 오늘 중심 약 3개월을 표시한다.
- 작업 전체가 30년을 넘으면 최초 보기만 최대 배율로 제한하고 이동하여 나머지 작업에 접근한다.
- 재진입 시 마지막 중심 날짜·날짜당 픽셀 수·세로 스크롤·그룹 펼침 상태를 복원한다.
- 창 크기 변경과 사이드바 토글은 중심 날짜와 날짜당 픽셀 수를 유지한다. 표시 범위의 넓이만 변한다. 최소·최대 배율 제한에 닿으면 그 제한을 우선한다.
- 표현 가능한 날짜 좌표를 벗어나는 팬은 경계에서 멈춘다. 1차 지원 달력 범위는 서기 0001~9999년으로 명시한다.

## 5. 프로젝트·작업·그룹 관리

### 5.1 작업 생성과 편집

- 그룹 선택 시 그 안에, 작업 선택 시 같은 부모 아래에, 선택이 없으면 프로젝트 최상위에 생성한다.
- 추가 버튼은 초안을 연다. 최초 저장 전 취소하면 작업을 생성하지 않는다.
- 이름은 필수이며 공백만 입력할 수 없다. 최대 200자를 제안한다.
- 날짜 미정 작업을 허용한다. 시작·종료일은 둘 다 입력하거나 둘 다 비운다.
- 날짜 미정 작업은 WBS 행에 ‘기간 미정’을 표시하고 막대는 표시하지 않는다.
- 같은 날 시작·종료하는 작업은 1일 작업이다. 종료일이 앞서면 저장을 차단하고 필드 옆에 오류를 표시한다.
- 수정 후 작업이 표시 구간 밖에 놓여도 자동으로 화면을 이동하지 않는다. 저장 성공은 알린다.
- 삭제 시 정렬 순서와 WBS 번호만 다시 계산한다. 다른 작업 날짜는 변경하지 않는다.

### 5.2 그룹

- 그룹도 이름, 개요, 호버 요약, 보드와 문서를 가진다.
- 그룹 시작일은 날짜가 있는 모든 후손의 최소 시작일, 종료일은 최대 종료일이다.
- 기간은 읽기 전용이며 ‘하위 작업에서 자동 계산’ 안내를 제공한다.
- 날짜가 있는 후손이 없으면 그룹 기간은 미정이다.
- 일부 후손이 날짜 미정이면 계산한 기간과 함께 ‘기간 미정 작업 N개’를 표시한다.
- 접힘 상태는 내용 데이터와 분리한 보기 상태로 저장한다.
- 일반 작업을 암묵적으로 그룹으로 변환하지 않는다.
- 작업·그룹 이동 메뉴에서 대상 그룹을 지정한다. 같은 프로젝트 안에서만 이동한다.
- 부모를 자기 자신 또는 자기 후손으로 지정할 수 없다.
- 이동 후 기존·새 조상 그룹 기간과 WBS 번호를 갱신한다.
- 그룹 삭제는 하위 항목 수를 명시하고 확인한 뒤 한 번의 원자적 저장으로 처리한다.
- 프로젝트 간 작업 이동은 1차 범위에서 제외한다.

### 5.3 호버 툴팁

- 막대 위에서 350ms 머무르면 표시한다. 휠·팬 중에는 표시하지 않는다.
- 구성은 작업명, 기간 또는 미정, 사용자가 작성한 호버 요약이다.
- 요약은 개요와 별도 필드이며 개요를 자동으로 복제하지 않는다.
- 요약이 비어 있으면 작업명과 기간만 표시한다.
- 일반 텍스트와 줄바꿈을 허용한다. 최대 500자를 제안한다.
- 화면 가장자리를 넘지 않도록 위치를 보정한다. 편집·클릭 기능을 넣지 않는다.
- 포인터가 벗어나거나 상세를 열면 닫는다. 키보드로 막대에 포커스해도 같은 정보를 제공한다.

### 5.4 막대 드래그로 일정 이동

- 막대 본문에서 왼쪽 버튼을 누르고 4px 이상 움직이면 일정 이동을 시작한다. 빈 공간의 팬과 별도 입력으로 처리한다.
- 드래그 시작 시 원래 날짜와 시간 배율을 보관한다. 포인터 이동을 날짜 차이로 변환하고 가장 가까운 정수 일수로 반올림한다.
- 새 시작일 = 원래 시작일 + 이동 일수, 새 종료일 = 원래 종료일 + 같은 이동 일수다. 기간 길이와 작업의 부모·순서는 바뀌지 않는다.
- 최소 이동 단위는 1일이다. 넓은 연도 보기에서 정밀 이동이 어려우면 Ctrl+휠로 확대한 뒤 이동한다.
- 이동 중 막대와 시작·종료일 미리보기를 표시한다. 조상 그룹 기간도 미리보기로 갱신하되 저장은 하지 않는다.
- 드래그 중에는 휠 줌·팬을 잠시 막아 기준 배율을 유지한다. 1차 구현은 화면 가장자리 자동 스크롤을 제공하지 않는다.
- 포인터를 놓으면 날짜와 관련 집계를 한 번에 저장한다. 이동량 0일이면 저장하지 않는다.
- Esc·pointercancel·예기치 않은 포인터 캡처 해제는 취소하며 원래 막대와 집계로 복원한다. 정상 pointerup 저장 이후의 캡처 해제는 취소로 처리하지 않는다.
- 지원 달력 범위를 넘는 이동은 허용하지 않는다. 저장 실패 시 원래 날짜로 복원하고 실패를 알린다.
- 드래그가 완료된 직후 발생하는 클릭은 상세 열기로 처리하지 않는다. 이동 없는 더블클릭은 기존처럼 상세를 연다.
- 날짜 미정 작업은 막대가 없으므로 상세에서 날짜를 지정한 뒤 이동한다. 막대 끝을 늘려 기간 길이를 변경하는 기능은 이번 범위에 포함하지 않는다.

### 5.5 일정 잠금

- 잠금 범위는 **날짜 변경**이다. 작업명·개요·호버 요약·노트·문서 편집은 가능하다.
- 일반 작업에 isScheduleLocked를 저장한다. 신규 작업의 기본값은 false다.
- 작업 행과 상세에 같은 잠금 토글을 제공하고, 잠긴 막대에 자물쇠 표시를 붙인다. 버튼에는 현재 상태와 잠금/해제 동작 이름을 제공한다.
- 잠긴 작업의 막대 드래그와 상세 시작일·종료일 편집을 모두 차단한다. 날짜 미정 작업도 잠그면 날짜 지정이 차단된다.
- 잠금은 화면뿐 아니라 날짜 변경 명령에서도 검사한다. 드래그 시작 시와 저장 직전에 다시 검사한다.
- 잠금 변경은 즉시 저장한다. 실패하면 이전 상태를 유지하고 오류를 알린다. 상세 편집 초안에 날짜 변경이 남아 있으면 먼저 저장하거나 버린 뒤 잠그도록 안내한다.
- 잠긴 막대에서도 호버·선택·더블클릭은 가능하다. 드래그 시도는 보드 팬으로 전환하지 않고 ‘일정이 잠겨 있습니다’ 안내를 제공한다.
- 1차 잠금은 작업 단위다. 그룹 전체 잠금·상속은 제공하지 않으며 그룹 기간은 하위 일정에서 계속 계산한다.
- 잠금은 삭제 방지나 접근 권한 기능이 아니다. 삭제는 기존 삭제 확인 규칙을 따른다.

## 6. 작업 상세

### 6.1 화면·초안·저장

상세는 넓은 대화상자로 연다. 왼쪽에 기본 정보, 오른쪽에 노트 보드와 문서 탭을 둔다. 배경 입력을 차단하고 포커스를 내부에 유지한다.

```text
┌───────────────────────────────────────────────────────────────┐
│ 작업 상세 / 작업명                                      [닫기] │
├───────────────────┬───────────────────────────────────────────┤
│ 이름              │ [자유 배치 보드] [상세 문서]              │
│ 시작일 / 종료일   │                                           │
│ 개요              │ 메모 공간 또는 서식 문서 편집기           │
│ 호버 요약         │                                           │
├───────────────────┴───────────────────────────────────────────┤
│ 오류·저장 상태                                 [취소] [저장]  │
└───────────────────────────────────────────────────────────────┘
```

- 열 때 저장 내용으로 편집 초안을 만든다. 탭 전환은 초안을 유지한다.
- 기본 정보·메모 배치·문서를 한 트랜잭션으로 반영한다.
- 저장 중 중복 입력을 막는다. 실패하면 창과 초안을 유지하고 재시도를 제공한다.
- 성공 시 목록·막대·조상 그룹 기간을 갱신하고 창을 닫는다.
- 변경 없이 닫기·Esc는 즉시 닫는다. 변경이 있으면 저장 / 변경 버리기 / 계속 편집을 선택하게 한다.
- 닫은 뒤 포커스를 원래 작업으로 복원한다.
- 개요는 2,000자 일반 텍스트를 초기 기준으로 한다.

### 6.2 자유 배치 노트 보드

피그마에서 느낄 수 있는 공간 탐색과 오브젝트 배치 방식을 적용한다. 1차 범위는 텍스트 메모 중심이다.

**1차 제공 기능**

- 텍스트 메모 생성·선택·내용 수정·이동·크기 변경·삭제.
- x/y, 너비/높이, 겹침 순서 저장.
- 빈 공간 드래그로 팬, 휠로 포인터 기준 확대·축소.
- 텍스트 편집 중 휠은 해당 입력 내용만 스크롤한다.
- 메모 상단 핸들은 이동, 텍스트 영역 드래그는 텍스트 선택이다.
- Delete는 선택 메모를 삭제하되 텍스트 편집 중에는 글자를 삭제한다.
- 화면 밖 메모를 찾기 위한 ‘내용에 맞춤’. 노트 보드 내부 기능이며 메인 일정의 기간 설정 UI와 구분한다.
- 위치를 화면 픽셀이 아닌 보드 좌표로 저장하여 확대 배율과 독립적으로 유지한다.
- 이동·크기 변경은 한 조작을 한 단계로 되돌릴 수 있게 한다.

이미지 첨부, 도형, 연결선, 다중 선택, 정렬, 프레임, 공동 커서는 후속 범위다. 파일 관리·권한은 해당 단계에서 설계한다.

### 6.3 상세 문서

- 보드와 별도 내용이지만 동일 작업에 귀속된다. 한쪽 수정이 다른 쪽을 덮어쓰지 않는다.
- 기본 템플릿은 목적 / 세부 작업 / 참고·결정 사항 / 완료 조건이다.
- 제목, 본문, 글머리 목록, 번호 목록, 체크리스트, 굵게, 링크를 1차 서식으로 제공한다.
- 템플릿은 최초 생성에만 적용한다. 사용자가 비운 문서에 기본 문구를 재삽입하지 않는다.
- 문서 내부에 작업 일정이나 진행률을 자동 연동하지 않는다.
- 구조화된 문서 형식과 스키마 버전을 함께 저장한다.
- 붙여넣은 스크립트나 허용하지 않는 HTML은 실행하지 않는다. 링크는 안전한 프로토콜만 허용한다.
- 작업 상세는 한 작업당 문서 하나를 제공한다. 아래 프로젝트 상세의 여러 문서와 별개다. 문서 버전 이력은 후속 범위다.

### 6.4 프로젝트 상세와 여러 문서

- 프로젝트명 옆 상세 버튼 또는 프로젝트 메뉴에서 연다. 프로젝트 선택은 기존처럼 일정 보드를 전환하며 자동으로 상세를 열지는 않는다.
- 상단에는 프로젝트명과 닫기, 문서 영역에는 ‘문서 추가’를 제공한다. 창 최대 높이는 화면 높이의 90%로 제한한다.
- 문서는 순서대로 세로 나열한다. 각 문서 블록에 제목, 본문 편집기, 접기/펼치기, 저장, 삭제를 둔다.
- 문서 영역은 남은 창 높이를 사용하고 내용이 넘으면 내부 세로 스크롤한다. 상단 제목과 문서 추가 버튼은 고정한다. 배경 일정 보드는 스크롤하지 않는다.
- 개수에 임의의 상한을 두지 않는다. 저장 공간 부족 등 실제 실패는 오류로 알리고 입력 초안을 보존한다.
- 추가 시 목록 끝에 새 문서 초안을 만들고 해당 위치로 스크롤해 제목에 포커스한다. 저장 전 취소하면 생성하지 않는다.
- 제목은 필수이며 최대 200자다. 같은 제목을 허용하고 ID로 구분한다. 본문은 비워 둘 수 있다.
- 문서마다 목적 / 세부 작업 / 참고·결정 / 완료 조건 템플릿 또는 빈 문서로 시작할 수 있다. 기존 본문에 템플릿을 자동 재삽입하지 않는다.
- 본문 서식은 작업 문서와 같은 규칙을 사용한다. 프로젝트 문서들은 작업 문서나 다른 프로젝트의 문서와 독립적으로 저장한다.
- 생성 순서로 표시하며 위로/아래로 이동 메뉴로 순서를 변경한다. 순서는 프로젝트별로 저장한다.
- 저장과 삭제는 문서 단위로 수행한다. 삭제는 대상 제목을 표시하고 확인하며 다른 문서에 영향을 주지 않는다.
- 여러 문서를 편집한 채 닫으면 ‘모두 저장 / 변경 버리기 / 계속 편집’을 제공한다. 모두 저장은 변경 문서들을 원자적으로 반영하고 실패 시 창과 초안을 유지한다.
- 문서가 많을 때 접힌 문서의 편집기를 생성하지 않고 펼칠 때 본문을 읽는다. 편집기 가상화를 사용하더라도 스크롤로 초안·커서 상태가 사라지지 않게 한다.
- 문서가 없으면 첫 문서 추가 안내를 표시한다. 프로젝트 삭제 시 소속 문서도 같은 트랜잭션에서 삭제한다.

WorkItem에 isScheduleLocked: boolean을 추가한다. 날짜 변경 명령은 이 값을 검증하며, 잠금 변경 명령과 일반 내용 편집 명령을 구분한다.

### 7.1 저장 불변 조건

1. ID는 안정적인 고유 ID다. 배열 순번·이름·WBS 번호를 식별자로 사용하지 않는다.
2. 작업 부모는 같은 프로젝트의 그룹이다. 루트이면 parentId를 비운다.
3. 폴더와 작업 계층에 순환을 허용하지 않는다.
4. 작업 날짜는 둘 다 비어 있거나 시작일 ≤ 종료일이다.
5. 그룹 날짜는 직접 저장하지 않는다. 후손에서 계산하며 필요하면 갱신 가능한 캐시로만 둔다.
6. 일정은 YYYY-MM-DD 날짜로 저장한다. 시간대 변경으로 하루가 이동하지 않게 한다.
7. 생성·수정 시각은 일정 날짜와 별도의 타임스탬프다.
8. 화면 변환에는 일 단위 좌표를 사용한다. 종료일은 포함이며 렌더링에서는 [시작일, 종료일+1일) 구간으로 계산한다.
9. 작업 삭제 시 보드 오브젝트와 문서를 함께 처리하여 참조를 남기지 않는다.
10. 보기 상태 저장 실패와 작업 저장 성공은 별개다. 보기 변경은 내용의 updatedAt을 바꾸지 않는다.


- 단기 화면 상태: 호버, 드래그 초안, 상세 초안, 휠 누적량.
- 내용 상태: 프로젝트, 작업, 보드 오브젝트, 문서.
- 보기 상태: 시간 중심·배율, 세로 위치, 사이드바·그룹 접힘.
- 내용과 보기를 분리하여 확대·축소가 미저장 작업 표시를 발생시키지 않게 한다.

### 8.2 타임라인 렌더링

- 작업 트리를 펼침 상태에 따라 평탄화하고 두 열이 같은 결과를 사용한다.
- dateToX / xToDate를 순수 함수로 분리하여 입력·렌더링에서 공유한다.
- 전체 수십 년을 하루 단위 DOM으로 생성하지 않는다. 보이는 눈금과 행만 만든다.
- 많은 행은 가시 행과 앞뒤 여유 행만 렌더링한다. WBS와 막대의 가상화 범위를 통일한다.
- 초기 화면에서 모든 상세 문서를 읽지 않는다. 작업 상세를 열 때 불러온다.
- 작업 날짜 변경 시 해당 작업과 조상 그룹만 다시 집계한다.
- 비수동 휠 리스너는 기본 스크롤 차단이 필요한 일정 영역에만 연결하고 해제 시 정리한다.
- 드래그는 포인터 캡처를 사용한다. pointerup·pointercancel·캡처 해제에서 종료한다.
- 4px 이상 이동했을 때 팬으로 판단하여 클릭과 구분한다.

### 8.3 노트 보드

- 월드/화면 좌표 변환을 타임라인과 분리한다.
- 이동·크기 변경 중 화면을 갱신하고 조작 종료 시 초안에 반영한다.
- 현재 표시 범위 밖 오브젝트의 렌더링을 줄일 수 있도록 경계를 계산한다.
- 텍스트 메모에 필요한 최소 구현을 우선한다. 도형·연결선용 범용 엔진을 미리 구축하지 않는다.

### 8.4 저장·복구

- 실제 제품은 재실행 후 데이터를 복원하는 영구 저장이 필수다.
- 프로젝트 이름 변경·이동·생성은 명령 성공 시 저장한다. 상세는 저장 버튼을 기준으로 한다.
- 보기 상태는 입력이 멈춘 뒤 약 500ms에 지연 저장한다. 이전 값이 최신 값을 덮지 않도록 순서를 보장한다.
- 저장 실패를 성공으로 표시하지 않는다. 초안을 보존한다.
- 스키마 버전을 관리하고 마이그레이션 성공 후에만 적용 완료로 기록한다.
- 로컬 파일이면 임시 파일 기록 후 교체 등 원자적 쓰기, DB이면 트랜잭션을 사용한다.
- 내보내기·가져오기와 자동 백업 UI는 1차 필수 범위에 넣지 않는다. 저장 중 데이터 보존 검증은 포함한다.

## 9. 빈 화면·오류·접근성

| 상황 | 처리 |
| --- | --- |
| 프로젝트 없음 | 프로젝트 만들기와 안내 |
| 작업 없음 | 작업·그룹 생성 안내, 오늘 중심 시간축 |
| 표시 구간 내 막대 없음 | WBS 유지, 현재 구간에 일정이 없다는 안내 |
| 날짜 미정 작업만 있음 | 행 유지, 기간 미정 표시 |
| 잘못된 날짜 / 빈 이름 | 필드 오류, 저장 차단 |
| 저장 실패 | 초안 유지, 실패 이유와 재시도 |
| 선택 프로젝트 삭제 | 같은 폴더의 다음 프로젝트 또는 빈 화면 |
| 선택 작업 삭제 | 상세 닫기, 인접 행으로 포커스 이동 |
| 데이터 읽기 실패 | 성공한 빈 결과와 구분한 오류·재시도 |

- 토글은 aria-expanded와 대상 연결을 제공한다.
- 계층 항목은 키보드로 선택·펼침·접기가 가능해야 한다.
- 막대는 이름·기간을 접근성 이름으로 제공한다. 색만으로 그룹과 작업을 구분하지 않는다.
- 대화상자는 제목 연결, 포커스 트랩, Esc, 복귀 포커스를 구현한다.
- 타임라인 단축키는 해당 보드에 포커스가 있을 때만 처리한다. 입력창의 +, −, 방향키를 가로채지 않는다.
- 휠 이벤트마다 날짜 범위를 스크린리더로 읽지 않는다. 탐색이 멈췄을 때 요약 전달한다.

## 10. 개발 단계와 완료 조건

### 단계 1 — 화면과 시간 탐색

접이식 왼쪽 사이드바, 프로젝트 전환, 동기화된 WBS/막대, Ctrl+휠 줌, 일반 휠 가로 스크롤, 자동 눈금, 팬, 보기 상태를 구현한다.

완료 조건: 3년 일정에서 포인터 아래 날짜를 유지하며 확대한다. 사이드바 접기/펼치기 시 중심과 배율을 유지한다. 상단 날짜·단위·줌 입력이 없다.

### 단계 2 — 계층과 일정 편집

프로젝트/폴더와 작업/그룹 생성·이름 변경·이동·삭제, 날짜 검증, 미정 일정, 그룹 집계, WBS 번호, 막대 드래그 일정 이동과 일정 잠금을 구현한다.

완료 조건: 중첩 그룹의 작업을 이동·수정·삭제하면 양쪽 조상 기간과 번호가 일관되게 갱신된다. 순환 이동을 차단한다.

### 단계 3 — 상세와 노트

개요·호버, 상세 초안, 텍스트 메모 보드, 서식 문서, 탭 전환 유지, 변경 취소, 프로젝트 상세의 여러 문서와 내부 스크롤을 구현한다.

완료 조건: 보드와 문서를 함께 저장하고 다시 열어 내용·배치를 복원한다. 취소는 저장 데이터에 영향을 주지 않는다.

### 단계 4 — 저장과 안정화

확정 환경의 영구 저장, 트랜잭션, 상태 복원, 실패 처리, 키보드 접근성, 가상화를 적용한다. 저장 인터페이스와 기본 구현은 앞 단계부터 연결하고 이 단계에서 복구와 부하를 검증한다.

완료 조건: 종료·재실행 후 프로젝트와 상세 내용이 복원되고 저장 실패 시 초안이 유실되지 않는다. 아래 수용 테스트를 통과한다.

일정은 플랫폼·저장 기술·문서 편집 방식 확정 후 산정한다. 단계는 개발 순서와 완료 기준이며 인력·기간 견적은 아니다.

### 11.2 성능 목표와 방법

- 데이터: 프로젝트 20개, 선택 프로젝트 작업 2,000개, 깊이 8, 표시 구간 10년.
- 60Hz 데스크톱에서 휠·팬 중 표시 프레임 대부분이 16.7ms 안에 처리되는 것을 목표로 한다. 기준 PC와 실측 수치는 구현 시 기록한다.
- 초기 프로젝트 표시 목표 1초 이내. 저장소 읽기와 렌더링 시간을 구분해 측정한다.
- 화면 밖 전체 행·날짜를 DOM으로 유지하지 않는지 확인한다.
- 노트 메모 100개에서 이동·내용 수정 지연과 누락을 확인한다.
- 목표 미달 시 가시 범위·재집계 범위·렌더링 횟수를 먼저 확인한다.

날짜 변환·줌 기준점·그룹 집계·순환 검사는 단위 테스트, 저장 원자성과 초안은 통합 테스트, 휠·포커스·사이드바·입력 충돌은 실제 브라우저 또는 데스크톱 런타임으로 검증한다.

## 12. 현재 시안과 제품 구현의 경계

개정 04의 제품명 제안, 프로젝트 다중 문서, 막대 일정 이동, 잠금은 기획 문서에만 반영했다. 동봉 HTML은 변경하지 않았다.

동봉한 `wbs-wireframe.html`은 개정 02 시안이다. 이번 개정 03은 기획 문서만 변경했으므로 시안의 일반 휠 확대·축소와 Shift+휠 시간 이동은 이전 동작으로 남아 있다. 실제 개발에서는 본 문서의 Ctrl+휠 확대·축소 및 일반 휠 가로 스크롤 규칙을 따른다. 작업 상세의 노트 보드 입력 규칙은 이번 변경 대상이 아니다.

| 항목 | 현재 시안 | 제품 목표 |
| --- | --- | --- |
| 왼쪽 접이식 사이드바 | 제공 | 영구 상태 복원·폴더 관리 |
| 직접 표시 기간 UI 제거 | 반영 | 유지 |
| 휠 줌·포인터 날짜 고정 | 일반 휠 줌 제공, 개정 03 미반영 | Ctrl+휠 줌·일반 휠 가로 스크롤, 프레임 병합·입력 장치 검증 |
| 자동 눈금·팬 | 기본 제공 | 전환 여유 구간·중첩 방지·달력 경계 제한 |
| 사이드바 토글 시 보기 | 중심·배율 유지 | 동일, 복원 상태 저장 |
| 작업 그룹 | 샘플 2단계, 접기 제공 | 중첩 편집·이동·삭제 |
| 새 작업 | 첫 그룹에 즉시 추가, 표시 시작일부터 7일 | 선택 위치에 저장 시 생성, 기간 미정 허용 |
| 최초 표시 범위 | 샘플 2026~2028 고정 | 실제 작업 범위 기반 |
| 상세 보드 | 메모 추가·이동·텍스트 | 팬·줌·크기·삭제·되돌리기 |
| 상세 문서 | 템플릿 일반 텍스트 | 서식 편집기 |
| 저장 | 페이지 메모리 | 영구 저장·실패 처리·취소 초안 |
| 대량 행·고정 헤더 | 단순 렌더링 | 가상화·동기 스크롤·고정 시간축 |

모든 수용 기준이 시안에 구현되거나 검증된 것은 아니다. 시안은 화면·조작 검토용이며 본 문서가 제품 개발 기준이다.

## 13. 구현 착수 전 남은 선택

1. **실행 환경:** 설치형 데스크톱 또는 브라우저 웹. UI·도메인 규칙은 공통이며 저장·배포 방식이 달라진다.
2. **사용 범위:** 개인용 또는 공동 편집. 문서는 개인용 기준이며 공동 편집에는 별도 서버·충돌 해결·권한 설계가 필요하다.
3. **문서·보드 구현 수단:** 기존 편집 구성요소 활용 또는 최소 기능 직접 구현. 기술 선택 시 유지보수·라이선스·입력 품질을 검토한다.

담당자, 진행률, 작업 의존선, 자동 일정 계산, 알림, 대시보드, 공동 편집, 모바일 전용 UI는 이번 기본 개발 범위에 포함하지 않는다.
