# WBS List up 단계별 개발·검증 계획

작성일: 2026-11-09  
기준 문서: [개발 기획서](개발-기획서.md) 개정 04

## 진행 원칙

- 각 단계는 **구현 → 해당 단계의 단위·직접 영향 검증 → 실패 수정 → 완료 확인**을 하나의 작업으로 진행한다. 검증을 다음 단계로 미루지 않는다.
- 단계별 검증은 변경된 동작과 직접 영향을 받은 범위로 제한한다. 순수 로직은 단위 테스트, 저장·화면 입력처럼 단위 테스트만으로 확인할 수 없는 동작은 필요한 통합 또는 실제 실행 검증을 함께 수행한다.
- 통과한 검증은 추가 변경이나 새 실패 징후가 없으면 반복하거나 범위를 확대하지 않는다. 공통 모듈·저장 스키마·빌드 설정처럼 영향 범위가 넓은 변경은 직접 영향을 받는 기존 검증을 함께 선택한다.
- **전체 회귀 테스트는 모든 개발 단계가 완료된 후 최종 단계에서 한 번 수행한다.** 최종 검증에서 실패를 수정하면 수정 영향 범위를 먼저 검증하고, 최종 완료 판정을 위해 전체 회귀를 다시 수행한다.
- 각 단계의 완료 기록에는 변경 내용, 실제 수행한 검증과 결과, 남은 문제를 남긴다. 실행하지 않은 검증을 통과로 기재하지 않는다.
- 기획서의 T01~T28은 해당 기능을 만드는 단계에서 직접 검증하고, 최종 회귀에서 전체 사용자 흐름으로 다시 확인한다.

## 사전 결정 — 개발 착수 조건

- [x] 실행 환경: Windows 데스크톱, Electron. 개인용 단일 SQLite 데이터베이스를 사용한다.
- [x] 문서 편집: 5단계에서 Tiptap 오픈소스 편집기를 사용한다. 서식·링크와 구조화 문서에 적합하며 아직 설치하거나 입력 품질을 검증하지 않았다.
- [x] 로컬 실행은 `npm start`, 테스트는 `npm test`. 개발 실행의 저장 위치는 `%APPDATA%\PlanWeave\data\planweave.sqlite`다. 설치판은 앱 이름에 따른 userData 경로를 패키징 시 재확인한다.

**결정 근거와 제약:** Electron은 MIT, SQLite는 퍼블릭 도메인, Tiptap 오픈소스 코어는 MIT다. 배포 시 각 구성요소의 라이선스 고지를 포함한다. Electron은 별도 패키징 도구로 Windows 설치 파일을 만들 수 있으나 아직 구성·검증하지 않았다. SQLite의 트랜잭션으로 저장을 원자적으로 처리한다. Node의 `node:sqlite`는 안정화 과정에 있어 버전 변경 시 호환성 확인이 필요하다. 내용은 기본적으로 하나의 JSON 레코드에 저장하며, 6단계에서 프로젝트 문서 본문을 별도 테이블로 분리했다. 나머지 데이터는 7단계 성능 측정에 따라 세분화가 필요할 수 있다. 참고: [Electron 패키징](https://www.electronjs.org/docs/latest/tutorial/tutorial-packaging), [Tiptap 라이선스](https://tiptap.dev/docs/editor/getting-started/overview), [SQLite 저작권](https://sqlite.org/copyright.html), [Node SQLite](https://nodejs.org/api/sqlite.html).

## 7단계 — 접근성·대량 데이터·복구 안정화
